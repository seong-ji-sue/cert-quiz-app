# docs/ — 문서 파일 안내

이 디렉터리는 프로젝트의 **모든 설계 문서, 개발 명세, 작업 이력**을 관리합니다.

---

## 📁 파일 구조

```
docs/
├── README.md          ← 이 파일: 문서 목록 및 설명
├── WORKFLOW.md        ← 개발 워크플로우 전체 프로세스
├── PLAN.md            ← 서비스 기획 및 기능 명세
├── ARCH.md            ← 시스템 아키텍처 및 모노레포 구조
├── SCHEMA.md          ← DB 모델링 및 Prisma 스키마
├── FE_DEV.md          ← 프론트엔드 개발 명세 [작성 예정]
├── BE_DEV.md          ← 백엔드 개발 명세 [작성 예정]
├── review/            ← AI 코드 리뷰 기록
│   └── YYYY-MM-DD-브랜치명.md
└── history/           ← 날짜별 작업 이력
    └── YYYY-MM-DD.md
```

---

## 📄 각 파일 설명

### WORKFLOW.md
**목적**: 개발 전체 프로세스를 정의합니다.
- feature 브랜치 생성 → 개발 → AI 리뷰 → 검증 → 푸시 → Slack 알림 → 머지
- 커밋 컨벤션, 자율 실행 원칙, 승인 프로세스 포함

### PLAN.md
**목적**: 서비스 기능 기획안을 담습니다.
- Gemini/Grok와의 기획 협업 결과 반영
- 핵심 기능 명세 (PDF 업로드, AI 문제 추출, 퀴즈, 채점, 학습 이력)
- 개발 로드맵 (Phase 1~4)
- **갱신 시점**: 기획 변경 또는 새 기능 추가 시

### ARCH.md
**목적**: 시스템 아키텍처 및 모노레포 패키지 구조를 정의합니다.
- 현재 패키지 구조 다이어그램
- Module Federation 아키텍처 흐름
- 향후 NestJS 백엔드 설계
- 환경변수 관리 전략
- **갱신 시점**: 패키지 추가/변경, 인프라 구조 변경 시

### SCHEMA.md
**목적**: MariaDB 테이블 및 Prisma 스키마를 정의합니다.
- ERD 개요
- Prisma schema 코드 (User, Certificate, Question, QuizAttempt 등)
- 마이그레이션 명령어
- **갱신 시점**: 테이블 추가/변경 시

### FE_DEV.md *(작성 예정)*
**목적**: 프론트엔드 개발 명세서입니다.
- 페이지 목록 및 라우팅 구조
- 컴포넌트 설계 및 상태관리
- API 연동 명세
- **갱신 시점**: FE 기능 개발 시작 전/후

### BE_DEV.md *(작성 예정)*
**목적**: 백엔드 API 개발 명세서입니다.
- NestJS 모듈 구조
- REST API 엔드포인트 목록 (Method, URL, Request/Response)
- 인증/인가 흐름
- **갱신 시점**: BE 기능 개발 시작 전/후

## 📝 review/ — AI 코드 리뷰 기록

**파일명 규칙**: `YYYY-MM-DD-브랜치명.md`
**예시**: `2026-03-08-feature-auth-login.md`

각 리뷰 파일에는 다음이 포함됩니다:
- 리뷰 대상 브랜치 및 변경 파일 목록
- 항목별 검토 결과 (오류, 보안, 스타일, 의존성)
- 발견된 문제 및 수정 여부
- 최종 판정: ✅ 머지 가능 / ⚠️ 수정 후 재검토 / ❌ 머지 불가

---

## 📅 history/ — 날짜별 작업 이력

**파일명 규칙**: `YYYY-MM-DD.md`
**예시**: `2026-03-08.md`

각 히스토리 파일에는 다음이 포함됩니다:
- `[작업 내용]`: 수행한 개발 사항
- `[오류 기록]`: 발생 에러, 원인, 해결 방법
- `[결과 확인]`: 실행 결과 및 정상 동작 여부
